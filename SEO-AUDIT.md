## 1. Резюме — три главных приоритета

1. **🔴 Критично — canonical всех страниц указывает на главную.** В `index.html` захардкожен `<link rel="canonical" href="https://irina-design.vercel.app/">`, и ни одна страница его не переопределяет. Google считает `/about`, `/portfolio`, `/services`, `/contact` дублями главной → подстраницы не попадают в индекс независимо. Наблюдение это подтверждает: в индексе только главная (netlify-домен), на vercel-домене — ноль страниц.
2. **🟠 Высоко — «мягкие 404» на всех платформах.** Любой несуществующий URL возвращает HTTP 200 с оболочкой приложения (rewrite `/* → index.html`). Google может проиндексировать мусорные URL. `public/404.html` — мёртвый код с битым редиректом на `/irina-design/` (остаток от GitHub Pages).
3. **🟠 Высоко — контент и метаданные только через JS.** Статический HTML = 3,4 КБ пустой оболочки. Title/description/JSON-LD вставляются клиентским рендерингом (react-helmet-async). Google обычно рендерит JS, но с задержкой; Bing — хуже; AI-боты (GPTBot, PerplexityBot) и соцсети — часто вообще не рендерят и видят оболочку с тайтлом главной.

## 3. Находки (по цепочке: доступ → обнаружение → рендер → индексация → canonical → доставка → смысл)

### 3.1 Доступ (access) — ✅ ОК

- robots.txt: `Allow: /`, ссылка на sitemap — корректно на обеих платформах. Ничего не заблокировано.
- Все маршруты: HTTP 200, TTFB ~160 мс (Vercel) — быстро.

### 3.2 Обнаружение (discovery) — ⚠️

- **SITEMAP-1 | Мусор в sitemap.xml (observed).** В sitemap попали `/404` и `/google5b6109d09ed90c5a` — плагин `vite-plugin-sitemap` автоматически включает все `.html` из `public/`. Трата краулингового бюджета + `/404` — это soft-404 URL. **Фикс:** `Sitemap({ exclude: ['/404', '/google5b6109d09ed90c5a'] })`.
- IndexNow (Bing) не настроен — опционально для маленьких сайтов.

### 3.3 Получение / рендер (fetch/render) — ⚠️

- **RENDER-1 | Контент только клиентским JS (observed+inferred).** Статика = 3,4 КБ оболочка. Title/description/JSON-LD подставляются через react-helmet-async. Google рендерит (обычно), но: очередь рендеринга откладывает индексацию; не-JS-краулеры видят оболочку с тайтлом главной на всех URL. **Влияние:** среднее-высокое. **Стратегический фикс:** пре-рендеринг (vite-plugin-prerender / SSR) — выносит контент в статику.

### 3.4 Индексация (index eligibility) — ⚠️

- **SOFT404-1 | Нет настоящих 404 (observed).** Vercel: `vercel.json` rewrite `/(.*) → /index.html`; Netlify: `_redirects /* → /index.html 200`. Несуществующие URL отдают 200 + оболочку. **Фикс:** точечные rewrites только для реальных маршрутов → index.html, остальное → 404.html со статусом 404 (на Netlify `/* /404.html 404`; на Vercel — whitelist маршрутов, всё прочее отдаётся как 404).
- **404HTML-1 | Битый 404.html (observed).** Файл редиректит на `/irina-design/` — остаток GitHub Pages; если когда-либо отдастся, получится битый редирект. Заменить на нормальную страницу 404.
- **ADMIN-1 | /admin без noindex.** Логин-панель отдаётся 200 и без `noindex` — может попасть в индекс. **Фикс:** `X-Robots-Tag: noindex` (или meta robots) на /admin.

### 3.5 Canonical — ❌ Критично

- **CANON-1 | Все страницы canonical → главная (observed, в коде и на проде).** `index.html:10` — единственный canonical в проекте. `/about`, `/portfolio`, `/services`, `/contact`, `/admin` сигналят Google «мой канонический URL — `/`». Последствие: подстраницы склеиваются с главной и не ранжируются независимо — ровно то, что видно в индексе (только главная).
  **Фикс:** убрать canonical из index.html; задавать canonical per-page через Helmet (или скрипт на смене маршрута): `/` → `https://irina-design.vercel.app/`, `/about` → `.../about` и т.д.
- **DUAL-1 | Два домена, canonical на vercel.app (observed).** В индексе пока только netlify.app-главная; vercel.app — 0 страниц. Canonical-сигнал корректный (один предпочитаемый домен), но vercel.app пока не проиндексирован — вероятно, задержка краулинга/рендера. **Действие:** убедиться, что vercel.app отдаёт тот же контент (да), и ждать пересборки сигналов; при желании — закрепить домен через Search Console (нужен доступ).

### 3.6 Техническая доставка (technical delivery) — ✅/⚠️

- ✅ Пер-страничные title/description через Helmet (после рендера) — корректные, уникальные.
- ⚠️ **JSON-LD через JS (observed).** Home — `ProfessionalService`, Contact — `LocalBusiness`. Синтаксически правдоподобно, но в статике отсутствует; один и тот же бизнес описан двумя типами на двух страницах (мелочь). Не-JS-краулеры schema не видят.
- ⚠️ **OG/Twitter — только главная (observed).** `og:url`, `og:image` в статике жёстко на главную: при шаринге `/portfolio` или `/contact` в Facebook/Telegram покажется превью главной. `og:image` — webp (Facebook с webp работает нестабильно — лучше png/jpg).
- ✅ `lang="uk"`, картинки с alt и lazy-loading, webp+srcset, кэш: HTML `max-age=0` + ассеты `immutable` 1 год (обе платформы).
- ⚠️ **Vercel не отдаёт security-заголовки** (X-Frame-Options и др. есть только на Netlify через netlify.toml). Для SEO не критично, для безопасности — да.
